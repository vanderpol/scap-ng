## Installation and source snapshot

Use Linux x86_64 / CPython 3.12 for the pinned environment. The lock below is
platform-specific; it does not certify installation on Windows or macOS.
Windows content conversion means consuming Windows SCAP source, not running a
Windows scanner. From a source checkout:

```bash
python -m venv /tmp/scap-ng-rc-env
/tmp/scap-ng-rc-env/bin/python -m pip download --require-hashes \
  --only-binary=:all: \
  -r docs/audit/v04-package-acceptance/requirements-linux-py312.lock \
  --dest /tmp/scap-ng-wheels
/tmp/scap-ng-rc-env/bin/python -m pip install --no-index \
  --find-links /tmp/scap-ng-wheels --require-hashes \
  -r docs/audit/v04-package-acceptance/requirements-linux-py312.lock
python tools/build_versioned_toolchain.py --version 0.4.0 \
  --ref EXACT_COMMITTED_SHA --output-dir /tmp/scap-ng-toolchain
python tools/build_versioned_toolchain.py --verify /path/to/toolchain.zip
```

The archive contains the whole exact committed tree, including specification,
canonical schemas, capability contracts, dependencies lock, tests, source
fixtures and guides. Its manifest records source SHA and every file hash/size.
The candidate evidence supplies the matching offline wheelhouse and dependency

## Original source to native authoring and compiled package

All CLI outputs must be new directories. A wrong source hash fails closed.
Use `/tmp/scap-ng-rc-env/bin/python` as `python` below after installation.

```bash
# Strict source proof: emit only independently statically proved Rule closures.
python tools/v04_direct_converter.py /path/to/original-signed.zip \
  --sha256 EXACT_SOURCE_SHA256 --rule EXACT_XCCDF_RULE_ID \
  --verify --output /tmp/scap-ng-proved

# Explicit draft compatibility: schema-valid authoring and package verification.
python tools/v04_direct_converter.py /path/to/original-signed.zip \
  --sha256 EXACT_SOURCE_SHA256 --rule EXACT_XCCDF_RULE_ID \
  --draft --compile --output /tmp/scap-ng-draft

# Independently inspect package integrity, references, programs and operands.
python tools/verify_v04_package_consumer.py \
  /tmp/scap-ng-draft/CONVERTED_UNVERIFIED.scapng \
  --source-json /path/to/native-authoring-json.zip \
  --report /tmp/scap-ng-draft/independent-package.json
```

The independent reader's external-authoring arguments take ZIP files containing
only the JSON (or YAML) authoring files, without directory entries. The bounded
release gate creates these as `authoring-json.zip` / `authoring-yaml.zip` and
checks both serializations. The converter's `--compile` also invokes the
independent reader directly against its in-memory authoring documents.

`--all-rules` inventories every Rule and isolates expected per-Rule blockers;
`--inventory-only` emits no converted content. `--draft --verify` is rejected.
The release-only full-65 builder additionally attempts all 100 existing reviewed
capability mappings; ordinary CLI uses its explicit enabled registry
`tools/v04_direct_capabilities.json`. Neither is a statement that every source
shape in a capability is supported. Historical shared converter/upgrader paths
remain in [the runbook](../developer/CONVERTER-COMPILER-RUNBOOK.md).

## Status and compatibility boundary

| Ledger status | Meaning |
| --- | --- |
| CONVERTED_VERIFIED | Schema-valid and compiled; required independent static source proof retained by exact hashes. |
| CONVERTED_UNVERIFIED | Native Assessment generated; schema/compile/proof fields state separate gates. Compatibility parity remains unproved. |
| BLOCKED | No admitted native Assessment for this automated Rule; original retained with diagnostics. |
| MANUAL_OCIL_ONLY_PRESERVED | Original preserved; no invented native automated Assessment. |

The revised pinned 65-STIG ledger contains 4,258 verified-native, 2,559
unverified-native, 422 blocked-automated and 1,653 manual/OCIL Rules (8,892
total). All 6,817 native candidates compile; no new independent source proof is
claimed. Of the original primary blocker cohorts, 980/992 catalog, 1,181/1,184
`all_exist`, 338/381 import/export and 30/30 aggregation cases now convert as
unverified drafts. See [cohort receipt](../audit/v04-draft-recovery-20261030.json).

Overlapping warning counts must not be added to these disjoint totals. Compilation
and independent package verification do not establish original-source semantic
proof, scanner conformance, publisher signatures or runtime equivalence.

Draft-only exact NIWC `ds:uri` catalog chains retain their original QName and
hashes. Standard catalog entries remain preferred; missing/conflicting or
ambiguous targets fail closed, without arbitrary component searches.
Test `all_exist` may lower to `require.items_found: one_or_more` with original
token, IDs, hashes and Variable/Set context retained in the source trace. Field
and record existence are unchanged. No absent Item is synthesized. Missing
expected targets, incomplete collection, error and unknown cannot be inferred
to pass from a positive Item. Runtime handling is unproved, so these drafts
cannot inherit verified status.

Bounded check exports bind typed expected-state Inputs to Benchmark Parameters.
Publisher defaults and allowed values are retained; no organization value is
fabricated. Complex restrictions, acquisition Inputs, imports without a supported
adapter, casts and unsupported Variable compositions remain blocked. Draft
`count`, `split`, `substring` and multiple aggregation components preserve the
existing canonical migration-expression shape with explicit warnings. This
does not promote that isolated migration contract into a new normative grammar
or change the four existing legacy function outputs and proof hashes.

## Scope and remaining work

Inline/shared Objects, Test-level `capability`, explicit `require` field/record
existence and matching, and `and`/`or`/`one`/`xor` remain the committed model.
Deprecated/source-invalid Tests are excluded rather than repaired. Originals,
manual procedures and blocked source closures remain downloadable for review.
Partial native Benchmark projections do not claim complete policy, CPE,
applicability, manual migration or source publisher trust.

Independent proof of warning-admitted Rules, remaining functions/bindings,
unsupported capability/field shapes and scanner execution remain follow-on
work. The candidate is for pre-alpha authoring/toolchain evaluation. It is not
a production compliance scanner. The owner decides final publication after
reviewing the exact-SHA decision packet and licensing gap.
