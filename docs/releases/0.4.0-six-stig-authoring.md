## Reproduce the inventory and compilation

The following checked-in CLI commands operate on downloaded files without
access to a private CI environment:

```bash
python tools/audit_v04_review_readiness.py \
  --json-archive work/scap-ng-0.4.0-six-stigs.json.zip \
  --yaml-archive work/scap-ng-0.4.0-six-stigs.yaml.zip \
  --report work/review-readiness.json --assert-six

python tools/v04_native_bundle_compiler.py \
  --json-archive work/scap-ng-0.4.0-six-stigs.json.zip \
  --yaml-archive work/scap-ng-0.4.0-six-stigs.yaml.zip \
  --output-dir work/compiled --report work/compiled-report.json
```

See [Human-runnable scripts](../../tools/HUMAN-RUNNABLE-SCRIPTS.md) for setup,
schema checks and optional externally anchored signing. Both scripts fail on
invalid input rather than silently modifying authoring content. The review
inventory reports unusual patterns but does not prove their original-OVAL
equivalence.

## Explicit limitations

Native `.scapng` files now **are compiled**, with manifest, logical references,
and separately verified Test programs, but they remain **unsigned** and have
**not** been executed in an independent scanner. Original OVAL behavior across
all capability types, live-target runtime behavior, and publisher trust policy
are separate acceptance gates; none is established by schema/byte parity alone.

*Experimental SCAP-NG project content; not DISA-issued, Board-ratified, or
certified for operational scanning.*
