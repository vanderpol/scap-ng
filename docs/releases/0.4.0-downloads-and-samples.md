## First steps with the recommended human-readable ZIP

1. [Download the authoring review ZIP](https://github.com/vanderpol/scap-ng-evidence/releases/download/v04-human-readable-review-20261030-ab5cddd/scap-ng-0.4.0-human-readable-authoring-review.zip) and its [per-file SHA256 manifest](https://github.com/vanderpol/scap-ng-evidence/releases/download/v04-human-readable-review-20261030-ab5cddd/scap-ng-0.4.0-human-readable-authoring-review.zip.manifest.json). Verify the ZIP SHA256 against the manifest's `sha256` field: `6d96531200c5f140007365ceb32dbe04e203d7b373c9e0c207b1f241c5f7dcf2`. The manifest also contains a complete per-file SHA256 inventory for extracted files.
2. Extract and open `authoring/`. Each STIG has a short folder (for example `rhel_9/` or `ms_windows_11/`) with `benchmark.yaml`, `applicability.yaml`, `rules/`, and `assessments/automated/`. The original SV-ID names imported Rule/Assessment files. The `manual/` directory is reserved for **genuine native manual Assessments**; preserved OCIL-only originals are in `records/`, not fabricated editable YAML.
3. Follow native logical IDs for Rule-to-Assessment references, never physical filenames. Read `records/` for original source/blocked/manual status and `metadata/reflow-receipt.json` for the preserved proof/compile counts.
4. For annotated individual Assessments start with the [focused source-backed samples](../examples/README.md); for the complete authoring/CLI contract see the [native library guide](../developer/NATIVE-LIBRARY.md). The VS Code Assessment Studio remains separate work.

## If reproducing the internal v1 layout experiment

1. Download and verify the normalized review ZIP against [`SHA256SUMS.txt`](https://github.com/vanderpol/scap-ng-evidence/blob/v04-normalized-library-review-20261030-ff69d46b3/runs/v04-library/2026-10-30-all65-normalized-review-ff69d46b3/SHA256SUMS.txt). Its SHA256 is `a01ea589501bf8a53e5df68e50ca9478f19543d2bd3844546667fde743c28d8c`.
2. Extract it and open `content/` only for technical reproduction. Its `benchmarks/`, `rules/` and `assessments/local/` directories are **not the approved authoring structure**. Rule-to-Assessment links use **logical IDs**, not filename-relative paths.
3. Use [the small direct-generated 0.4 examples](../examples/README.md) for annotated, source-backed Test/`object`/`require` forms, or [illustrative Assessment syntax](../../specification/examples/assessments.md) for orientation. The latter is prose guidance; the pinned native files are the actual editable source.
4. Optionally extract the exact maintenance toolchain separately and run `python tools/scap_ng_library_cli.py check /path/to/library/content`. `analyze`/`check` do not modify source; `apply` requires a reviewed plan and explicit `--write`. [Full commands](../developer/NATIVE-LIBRARY.md).
5. Inspect `records/` for source identity, original-only Rules and proof/warning status. Five streams (four SQL Server and Tomcat) have source records but **no fabricated editable Benchmarks or Assessments**.

The normalized review preserves **65 original streams / 8,892 Rules**: 6,817 compiled native candidates comprising 4,258 independently statically proved and 2,559 **UNVERIFIED**; a further 422 automated Rules remain blocked and 1,653 manual/OCIL Rules remain preserved. The 13,754 native YAML payloads and all accepted program/proof hashes are unchanged from the DRAFT. Nothing here establishes live scanner parity or a publisher signature.
