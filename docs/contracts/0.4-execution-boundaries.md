# Collection, observation and explanation boundaries

Scope: existing frozen 0.4 requirements plus explicitly held acquisition choices.
This accompanies RI Issue #43's pre-handoff design. It changes no grammar or
native truth table. [Native evaluation](0.4-evaluation.md),
[evidence fidelity](0.4-evidence.md) and [compatibility](0.4-compatibility.json)
remain authoritative. Implementation examples are not scanner-equivalence proof.

| Existing native requirement | Consequence for implementation / conformance |
| --- | --- |
| A Test uses its selected logical Object population. Item and field cardinalities are independent. | Sharing a physical capture cannot merge different logical populations or deduplicate repeated field/Variable values. Require does not select acquisition evidence. |
| Collection status, logical/population completeness, Item status and value status are distinct. | EOF, successful storage, retained-report length and a matching value alone do not establish complete observation. Unknown/error/inaccessible evidence must not become confirmed absence or a known false comparison. |
| No synthetic missing collected Item. | Preserve acquisition diagnostics and actual Items; a missing binding is not an observed empty population. Empty/unknown/error reduction not established for the RI remains held. |
| Native identities, capability and source context bind observations. | A digest or matching capability alone does not establish source authenticity or permission to reuse evidence. Execution-context authorization is an implementation security boundary. |
| Native Result requirement pointers are assessment-relative `/tests/.../require/...`. | Resolve the actual requirement. RI request pointers rooted `/assessment/tests/...` are a different representation; presentation mapping cannot invent or blindly rewrite a source location. |
| `item_summary` and `items_observed` distinguish actual population/evaluation from returned evidence. | A capped report does not establish zero Items or change counts/completeness. Do not infer native mismatch counts from a final boolean or one decisive witness. |
| Result typed values support `redacted: true` and prohibit a `value` member in that case. | Redact exports after actual evaluation. Never substitute a string for a typed secret, disclose a low-entropy unsalted hash, or feed redacted evidence back as if it contained an observed value. RI evaluation of redacted envelopes is currently unsupported. |
| Native Test/field Results have mandatory source and observation members. | An RI internal Decision or opt-in explanation is not a full native Result. Added UI reason codes are not undeclared native Result properties. Validate a complete native export separately. |

## Proposed acquisition terminology — no new authored fields

Persisted configuration, loaded/runtime state, effective state for an explicit
context and restart/boot behavior name different observations. A provider's
read interval and actual consistency guarantee must be documented; a SQLite
snapshot does not establish host simultaneity. These are proposed provider/
provenance contracts under [Issue #53](https://github.com/vanderpol/scap-ng/issues/53),
not new required Collection Result fields. Existing schemas continue accepting
and rejecting exactly the same documents.

Where source OVAL reads a file and DISA manual text queries loaded state,
preserve source-compatible conversion and record the alignment question. A
source/policy correction or a requirement to check both states needs explicit
case review. No blanket auditctl/sshd substitution is approved. Frozen Registry
traversal rejection is preserved; next-version support direction does not settle
all views/codecs/statuses or authorize a frozen-schema edit.

## Result explanations and held behavior

A presentation view can display PASS/FAIL only from actual selected-Test
true/false. Diagnostic labels UNKNOWN/ERROR/UNSUPPORTED identify actual evidence
availability, operational errors or held support; they do not create native
technical outcomes or Definition/Rule roll-up. A cause not established by the actual
receipt must stay unspecified. Unknown/unrecorded counts remain absent, not zero.
Model A counts logical Variable sources, not fabricated collected Items.

Retain source requirements, actual scoped counts, decisive witnesses and safe
references during evaluation. A renderer must not recompute truth or retrieve a
new host observation. Default presentation suppresses sensitive values and raw
host identifiers. Authorized full export uses the existing redacted typed-value
mechanism and correct native fields; the selection/disclosure policy remains an
implementation/security review item. No new Result wire is adopted here.

## Conformance requirements and source compatibility

The [machine ledger](../../conformance/0.4/execution-boundaries/requirements.json)
contains exact native JSON pointers/file digests, original OVAL 5.12.3 XPaths/
file digests, disposition and required acceptance witnesses. OVAL is a historical
compatibility reference, not additional normative native behavior. Schema probes
in this increment verify existing redaction, exact property sets and pointer
roots only. They do not execute a native scanner or prove an outcome.

Future runtime gates: same population/typed values/status/counts for shared and
separate captures; privilege/view/binding mismatch isolation; mutation/reload
consistency; missing/denied/partial/canceled observations; redaction canaries and
trace limits; unchanged original 23 conformance outcomes and eight CLI responses.
Every approved behavior increment needs executable positive/negative witnesses
and linked RI regression evidence. Unresolved acquisition/status choices in #31–#34/#46/#53 require owner decisions.
Approved language features that the RI does not yet implement (including source
bindings or functions) are implementation limits, not new normative restrictions:
add them through scoped increments with conformance under their approved native
contracts. Definition roll-up remains outside the current RI scope. No proposed
fixture here establishes those results.
