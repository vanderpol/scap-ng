# Unresolved operational contracts

These holds do not block the approved complete-known-nonempty equality/Model A increment. They must be resolved before the corresponding features are implemented. No choice below is silently adopted.

| Gap | Exact alternatives / consequence | Recommendation for later owner review |
| --- | --- | --- |
| Empty source Variable | Zero logical sources; one source with an empty field; or an evaluation error. These change Item/field quantifier truth. OVAL constants require at least one value and cannot establish the native `literal: []` case. | Keep `zero_values` distinguishable; approve a separate source/field truth table before Test outcomes. Current RI diagnoses it. |
| Empty expected Variable | A vacuous comparison fold versus an explicit error/indeterminate result. OVAL State references with no values specify error; that is not yet an independent native rule. | Prefer explicit error over vacuous pass, but obtain approval and a full table first. |
| Error/unknown/incomplete precedence | Known matching subset versus authoritative total is different; a partial stream cannot establish `every`, `none` or unique cardinality. Native enums do not decide every combination. | Publish native reducer tables separating logical, population and evidence completeness. Preserve explicit diagnostics meanwhile. |
| Type compatibility / casts | Exact same type versus selected widening/coercions; source conversion functions contain casting rules not enumerated natively. | Same-datatype execution only until an explicit native compatibility/cast table is approved. Never round integers through floats. |
| `concat` casting/status | Known string Cartesian product/order is described; inherited conversion and mixed status combinations are incomplete as standalone native rules. | Qualify complete known string components separately; approve cast/status tables before broader inputs. Functions remain unimplemented here. |
| `unique` normalization/order | OVAL treats components as strings; native typed scalar deduplication does not settle all cast/order questions. | Do not import stringification. Specify supported datatypes, equality and output order explicitly before implementation. |
| Regex capture and merge edge cases | Regex dialect, no capture/no match/empty capture; merge sort collation and nonstring casts need precise rules. | Retain shape only, diagnose execution, and add explicit native vectors before support. |
| Six-state group/Definition aggregation | Known Boolean AND/OR, XOR parity and ONE exactly-one are distinct; error/unknown/not-evaluated/not-applicable precedence needs complete native tables. | Keep Test scope; approve standalone native aggregation tables and source witnesses before roll-up. No Definition outcomes in this increment. |
| Broader capability collection | Registry views/traversal; shell execution/STDERR; filesystem boundaries/times/ACLs; RPM query/EVR behavior are not established by supplied equality fixtures. | Keep collectors absent; qualify each native acquisition contract with platform evidence before implementation. |
