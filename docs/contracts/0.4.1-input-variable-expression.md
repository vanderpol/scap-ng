# SCAP-NG 0.4.1: Input operands and explicit integer conversion

**Status:** Canonical authoring proposal. Does not imply runtime or source-equivalence qualification.

`{"input": "<id>-input"}` is a typed expression leaf that reads the Assessment invocation's policy-bound Input. Its declared contract determines datatype, cardinality, and allowed values; neither the converter nor RI may substitute an XCCDF default for a missing runtime Input. Optional Input use remains subject to the existing `input_provided` guard.

`{"to_integer": <expression>}` explicitly parses each string operand as an OVAL-compatible decimal integer; signed decimal digits and leading zeros are accepted. Non-string operands, invalid lexical tokens, incomplete evidence, unbound required Inputs, and exceeded budgets fail closed. No silent coercion in arithmetic or reinstatement of Variable declaration datatypes.

Pinned Q3 2026 signed Oracle Linux 7 V3R3 V16 witness: Rule `SV-221718`, OVAL `def:518`, XCCDF `check-export` of `var_accounts_user_umask` (default `077`) to external `var:4211`. Three OVAL int Variables `var:4212`, `var:4213`, `var:4214` perform substring digit extraction and OVAL `var:3814` calculates `64*a+8*b+c`. Preserve the Input binding, digit conversion, and exact source arithmetic (not a hardcoded default or Rule-specific octal shortcut).

Admission gate: signed archive pin; schema validation; converted Rule replay; all XCCDF selectors `077`/`027`/`022`/`007`; missing/invalid Input behavior; independent RI/source equivalence proof; no regressions.

## Typed Input constraint expressions

Assessment Inputs may declare an optional `constraints.predicate` expression. The
expression reuses the native typed comparison vocabulary (`equals`, numeric and
version comparisons, `matches_regex`, and the other admitted comparison keys)
and the generic Boolean nodes `and`, `or`, `one`, and `xor`. It is deliberately a
value expression, not an OVAL object/state/restriction structure:

```yaml
constraints:
  allowed: [legacy-value]
  predicate:
    or:
      - matches_regex: '^123-[0-9]{3}-[0-9]{4}$'
      - and:
          - greater_than_or_equal: 10
          - less_than_or_equal: 20
```

`allowed` and `predicate` are alternatives (logical OR). Every supplied value
must satisfy at least one alternative; a multivalue Input is not reduced to its
first value. `cardinality` is checked independently before constraint matching,
and the converter derives it from the source consumer graph. If the source graph
does not establish a safe cardinality, conversion remains held rather than
assuming `exactly_one` from a fixture.

The authoring contract bounds each Boolean branch array to 64 entries and string
comparison literals/patterns to 4096 characters. These limits are denial-of-
service protections, not source expected outcomes. Exceeding them is an explicit
validation/resource error. Required Input omission remains `not_evaluated`;
optional omission requires a dominating `input_provided` guard; an unguarded
optional reference is an authoring error. Explicit empty populations remain
distinct from omission and are accepted only by a compatible cardinality.

No Input constraint contains a hidden default. A source external-variable fixture
is never copied into an Assessment or used when an invocation binding is absent.
