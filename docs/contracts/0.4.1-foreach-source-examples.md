# Source-backed `for_each` modernization examples

These examples are a design comparison, not conversion or runtime claims. The
source Rules and hashes are from the pinned Tools issue-83/PR-107 evidence
packet (`scap-ng-tools` source evidence, converter commit `8f0e562...`). The
current canonical 0.4.1 grammar and the proposed compact Object expansion are
compared without changing source state semantics.

| Source Rule (source Rule SHA-256) | Original OVAL shape | Current 0.4.1 representation | Proposed correlated form | Decision |
|---|---|---|---|---|
| `SV-278388` (`9dc19f9b84067d36a3e1fbce0baf13d1662a81e1e1d374f3eec5e40a814d8abf`) | NGINX dynamic Variable/Object graph selects discovered configuration records and applies a dependent check. | Separate converted Variables/Objects preserve the graph; no active `for_each` reference. | One source Object per discovered record, then a typed selector binding for the dependent NGINX lookup. | Candidate; source Item field contract required. |
| `SV-259338` (`055363a557decea13b74bf0f01cf6a937860f97d763cc742d25771cd1314a53a`) | DNS Windows dynamic Variable/Object graph fans out discovered names into dependent checks. | Variable/Object graph remains source-traced; transformation is not a selector alias. | Iterate discovered DNS Item identity and bind the reviewed selector field. | Candidate; Windows collector and binding type required. |
| `SV-230399` (`0eff6183b2dbfc293b444674e192a71c455dc80f7fd35acfdfd52c29b6de4e30`) | RHEL 8 source graph repeats a dependent package/config check for a discovered population. | Converted source graph uses named Objects/Variables because `for_each` was not active. | Iterate source Item and bind one scalar selector per dependent Object. | Candidate; preserve source cardinality and order. |
| `SV-230400` (`b6fb65dfcd7a0c111225e424b24d3a1c9ab084c7299f1b903b67369b77a51b5a`) | Adjacent RHEL 8 Rule with the same dynamic-population pattern but a different State predicate. | Separate converted Test/State predicate; no implicit sharing. | Reuse the source traversal and create a distinct dependent Test; reduction remains per source Item. | Candidate; verify compatible source Object reuse. |
| `SV-230401` (`406c86fddecbecc50ed2bd1bf57ccb53954766e0ece271d47484ae11f4005feb`) | Third RHEL 8 dynamic source/dependent closure. | Source identity and State remain separate in current NG. | Chained alias form only if the source itself is a bounded expansion; no sibling Cartesian product. | Candidate; cycle and depth checks required. |
| `SV-258166` (`d7f7c318bf5e260425458e45faec3ed1e3a47749e9810ba2d4de0bd15d68527a`) | RHEL 9 dynamic Variable/Object closure over discovered package/config data. | Converted Objects/Variables preserve provenance but cannot express per-Item selector correlation compactly. | Bind a typed source Item field to a reviewed Linux selector and retain one iteration Result per source Item. | Candidate; independent source-equivalence proof required. |

For the Windows IIS cases documented by the same packet (`SV-218752` and
`SV-214463`), the converter evidence currently recommends the generic
`unique` Variable lowering instead: their original graph has a source
Schematron mismatch (`appcmd_object` filter requires `appcmd_state` but the
content uses `appcmdlistconfig_state`). They are not silently presented as
`for_each` proof. This is an important negative example: compact syntax must
not conceal an invalid source graph.

The examples demonstrate where the feature could reduce repeated authoring;
they do not establish that the proposed representation is lossless. Each
requires source Item identity, selector datatype, cardinality, status,
completeness, and independent expected-result receipts before converter or RI
activation.
