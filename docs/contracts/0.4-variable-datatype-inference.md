# SCAP-NG 0.4 Variable type inference — owner-approved authoring change

Status: candidate canonical 0.4.0 contract, stacked on draft PR #64; **not yet merged or released**. Source decision: [Issue #28](https://github.com/vanderpol/scap-ng/issues/28), owner approval 2026-11-13.

## Native authored shape

A Variable declaration has `kind` and `expression` (optional title). The redundant declaration-level `datatype` is **removed**, not silently treated as a no-op. Typed literal payloads retain `datatype` where a specific non-JSON scalar domain is needed. Collected Item fields, explicitly typed Inputs, individual Require comparator semantics and typed evidence are **unchanged**.

Before:

```yaml
variables:
  file-count-variable:
    kind: local
    datatype: integer
    expression:
      count:
        values:
          object: {object_ref: files-object}
          field: full_path
```

After:

```yaml
variables:
  file-count-variable:
    kind: local
    expression:
      count:
        values:
          object: {object_ref: files-object}
          field: full_path
```

To distinguish a version literal from a lexical string:

```yaml
variables:
  target-version-variable:
    kind: constant
    expression:
      literal: {datatype: version, value: "1.02"}
```

## Inference rules

| Expression | Type domain | Independent caveat |
| --- | --- | --- |
| `literal` scalar or list | JSON string/integer/float/boolean, or typed payload's declared domain | `"001"` is string, never an inferred integer; `[]` has no scalar type until a consumer constrains it |
| `variable` | referenced resolved Variable type | reject cycles, unknown references |
| `values` | canonical Item field type(s), **not** the raw field's string appearance | unavailable/ambiguous capability field => hold, do not guess |
| `count` | integer | successful empty => 0; missing/error/incomplete NOT 0 |
| `split`, `substring`, `concat`, `regex_capture`, `begin`, `end`, `merge` | string | validate input domain and the function's existing source-aware contract; preserve duplicates and order |
| `arithmetic` | integer if all inputs integer, otherwise float if any float | numeric operands only; no numeric-looking string coercion |
| `unique` | inherited from operand(s) | preserve first-occurrence ordering, number of values changes, scalar type does not |
| Other/unknown | none | fail closed; no generic function envelope or implicit cast |

**Independent axes:** datatype ≠ population/cardinality ≠ source observation status. An empty **successful** collection is not the same as denied/incomplete/not-collected; infer no scalar type from empty values alone. The compiler must check the consuming comparison's type and domain, not only the Variable's syntax. The collector remains responsible for emitting typed Items.

### Source conversion boundary

Do not drop source OVAL `local_variable/@datatype` tokens or reconstruct them from expression type. They remain in migration provenance. Source Variable declaration and native expression result may disagree: OpenSCAP has exhibited numeric-to-string and split-string-to-integer coercions in older content, including conversion errors. **Do not promote such a conversion as equivalent** unless source behavior was independently proved or an explicitly approved compatibility adapter exists. No hidden casts.

### Dependent implementation requirements

- `scap-ng-tools`: preserve source type in trace/provenance, omit declaration `datatype` in native output, retain typed literal payloads, infer recursively via canonical field/function semantics, keep cross-domain ambiguous input blocked.
- `scap-ng-vscode`: take declaration shape and available operators from **exact pinned schema**, never show a redundant Variable datatype editor after repin; show inferred type as derived read-only context, with a warning for ambiguous/legacy declaration fields. YAML edits must not silently delete unsupported legacy fields before explicit migration.
- `scap-ng-ri`: resolve Variable type from expression/collected field, never from now-removed declaration `datatype`; preserve status/cardinality independence, return a diagnostic if type cannot be inferred.
- All pinned schema family hashes, editor packs, converter schema snapshots, sample goldens, and release receipts need coordinated regeneration and CI. No source/RI equivalence is established by a passing JSON Schema test.

### Versioning / compatibility

This is a **breaking authoring shape within pre-release 0.4.0**: old authored declarations containing `datatype` need an explicit migration. Do not claim no change to older files' validity. Keep frozen historical schema hashes intact. Stack the candidate onto draft PR #64 rather than changing an active published schema behind consumers. Do not merge/publish the three repository updates separately.
