# SCAP 1.4 applicability inheritance (SCAP-NG 0.4.1)

Status: coordinated draft contract; not a release or 65-benchmark qualification.

## Audit conclusion

XCCDF 1.2/SCAP 1.4 carries `platform` on the Benchmark, Group and Rule
items. A platform restriction is inherited by descendants; a Rule-local
restriction does not replace an ancestor. The effective predicate is therefore
`Benchmark AND every Group ancestor AND Rule-local`. Multiple `platform`
elements on one XCCDF item form that item's alternative platform set (OR).
The CPE language used by a referenced platform specification is evaluated as
its own Boolean tree: `AND`, `OR` and `NOT`/`negate` are not flattened into a
list of names.

Profile selection is a different axis. Effective profile selection is applied
before scheduling a Rule. A profile-disabled Rule is `not_evaluated` with
reason `profile_disabled`; it is never the same result as a Rule whose
applicability predicate is FALSE (`not_applicable`). A profile does not rewrite
or disable an applicability expression.

The prior converter incorrectly copied every ancestor `platform` reference
into each emitted Rule. That output loses the source path, can turn ancestor
AND into an accidental local expression, and makes native execution unable to
identify which restriction caused a result.

## 0.4.1 schema change

0.4.0 is historical and untouched. The active 0.4.1 flat schema now defines:

* `benchmark.platform.applicability`: optional Boolean expression;
* recursive `benchmark.groups[]` entries with `id`, `groups`, `rules`, and
  optional Group-local `applicability`;
* `rule.applicability`: optional Rule-local Boolean expression (removed from
  the required list);
* `applicability.schema.json#/$defs/expression`, with exactly one of
  `condition`, `all_of`, `any_of`, or `not`;
* catalog condition `source` provenance (`kind`, source `id`, SHA-256, and
  optional `href`). `assessment` is optional only for an unqualified source
  identity. Missing executable mapping is an applicability ERROR, never FALSE.

An omitted applicability field means no restriction at that level. The schema
must not require an empty/synthetic condition to represent that case.

## Runtime truth table

| Applicability condition | Rule result | Collection scheduled? |
| --- | --- | --- |
| TRUE | normal Assessment result | yes |
| FALSE | `not_applicable` | no |
| UNKNOWN | `unknown`, reason `applicability_unknown` | no |
| ERROR / no qualified mapping | `error`, reason `applicability_error` | no |
| profile disabled | `not_evaluated`, reason `profile_disabled` | no |

For `all_of`, FALSE dominates UNKNOWN/ERROR; otherwise ERROR dominates
UNKNOWN. For `any_of`, TRUE dominates UNKNOWN/ERROR; otherwise ERROR dominates
UNKNOWN. This is only the aggregation of already evaluated conditions;
collection/evaluation errors are never silently converted to false.

## Converter and provenance

The converter now records per-Rule `source_applicability.levels` in source
order. Each level retains its source kind/id and each platform child retains
its source `idref` and XML digest. Nested Groups are emitted recursively;
Rule-local, Group-local and Benchmark-local predicates are not merged. The
catalog condition key is only a stable reference to a source platform and is
not a fabricated executable Assessment.

A source platform without a qualified native mapping remains an explicit
hold. It may be inventoried and carried with provenance, but it cannot be
promoted to a scanner-qualified result. No historical or normalized 65-stream
corpus is regenerated by this change.

## Regression coverage and unresolved decisions

The coordinated drafts include vectors for Benchmark → nested Group → Rule,
multiple local platform alternatives, nested Boolean expressions, unknown and
error applicability, and profile-disabled Rules. The remaining owner decision
is qualification of each CPE fact/OVAL platform Assessment mapping (including
platform facts whose source is a CPE URI). Until those mappings are pinned and
independently qualified, such conditions must produce ERROR/hold rather than
not_applicable.
