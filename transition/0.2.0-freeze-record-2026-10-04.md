## Branch audit and branch-management rule

Branch state is now a durable repository artifact.

- Root-level `BRANCH-MANAGEMENT.md` records purpose, status, relationship to `main`, and disposition for non-main branches.
- `AGENTS.md` requires every repository task to read `BRANCH-MANAGEMENT.md` during preflight.
- Accepted 0.2.0 work found on freeze-related branches was reconciled to `main`.
- Explicitly deferred ESX work remains held rather than merged.
- Historical/diverged experiments are classified rather than assumed to contain missing accepted work.

See `BRANCH-MANAGEMENT.md` for the current registry.

## Human-audit claim boundary

This freeze is based on extensive automated validation plus targeted design review, but it SHALL NOT be represented as an exhaustive independent human semantic audit of every 0.2.0 capability and interaction. The project owner explicitly requested stronger human-audit discipline for subsequent evolution.

Future semantic changes must follow `MAINTAINING.md`: focused before/after examples, source evidence, compatibility impact, focused tests, machine evidence, and explicit human acceptance. A green workflow alone does not establish acceptance.
