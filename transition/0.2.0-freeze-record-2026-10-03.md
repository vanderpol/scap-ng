## 0.2.0 closure decisions included in this baseline

### Direct Variable zero-value semantics

A directly tested `variable.value` Variable that resolves successfully to zero
values produces technical `error` before State/value comparison.

An empty string is one value, not zero values.

Focused truth-table regression exists.

### Native authored literals

0.2.0 native authored scalar literals use native JSON/YAML typing.

Examples:

- Boolean: `false`, not `"false"`;
- integer: native integer, not Boolean or numeric string;
- float: finite native numeric value;
- record: structured representation, not scalar literal.

Legacy XML lexical aliases are migration/import concerns and are normalized
before emitting native 0.2.0 authored content.

Semantic-validator regressions cover these boundaries.

### OVAL 6.0-only Tests

OVAL 5.12.3 remains the baseline for existing semantics.

Only genuinely new OVAL 6.0 Tests were considered for this review.

- ESX expansion: **deferred pending upstream guidance**.
- `kubepsp_test`: **deferred** because it targets removed PodSecurityPolicy
  semantics and lacks a modern native-platform justification.
- `kubectl_test`: **deferred** pending a native Kubernetes resource/API model
  and conformance evidence.

These Tests are reviewed/deferred, not an unimplemented 0.2.0 freeze backlog.

### Conformance evidence layers

The draft specification now distinguishes:

1. serialization/schema validity;
2. semantic validity;
3. known-result evaluator conformance;
4. collection/acquisition conformance;
5. live-target execution conformance;
6. migration-equivalence evidence.

Evidence at one layer does not prove a stronger layer.

This distinction is explicitly cross-linked from Results so synthetic Items,
result completeness, and live collector conformance are not conflated.
