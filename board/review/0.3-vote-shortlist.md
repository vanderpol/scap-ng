## Format

Aim for **six independent questions**, each answerable in under a minute. Publish only after the technical choices and examples have been checked for 0.3; the Board may support five questions and reject the sixth. Allow a clearly identified alternative/“other” and an optional explanation. Detailed justification stays behind a link, not in each opening post.

**Non-negotiable for every ballot:** faithful forward migration from supported SCAP 1.4/XCCDF and OVAL 5.12.3 (or precise diagnostics for unsupported/deprecated constructs); explicit six-state meaning, quantifiers, applicability, provenance, and evidence. No alternative is permission to rewrite or silently lose source semantics. Schema validation alone does not establish equivalence.

### Questions intentionally *not* sent as votes in this round

- **Established technical contract:** Benchmark → Rule → Assessment; no authored Policy indirection; actual source applicability tests, not CPE magic; local Test expectations and Object/Set **embedded Filters**, with no separately reusable authored State; explicit quantifiers, source fidelity, resource-limit diagnostics, and evidence completeness. The Board can review the design, but asking to “vote” on basic correctness or losslessness is misleading.
- **Already deferred or research-only:** assessment-native informational role (P023), inline Manual Assessment shorthand (P043), optional speculative CPE matching capability (P048), a second authored language/execution front end (P053, distinct from V1 *vocabulary preference*), and mandatory CBOR/JSONL alternatives (P055). Revisit only with a bounded concrete interoperability issue.
- **Superseded proposals not publishable verbatim:** P007 (repeats State capability), P008 (retains named/reused Filter States), P016 (older narrow scope wording), P020 (presumes named local States), P058 (reads as if all conditional authoring should be deferred). Reconcile with the maintained [local predicate contract](../../specification/assessment/selection-and-filters.md) and [0.3 conditional scope](../../research/iterations/003/design/CURRENT-DESIGN.md).

## Publication and cleanup gate

1. Owner reviews and adjusts the shortlist. **Do not publish new ballots, close threads, or delete old ones yet.**
2. Repair inconsistencies in the **ballot text and supporting examples**, *not* silently in the normative schema. Each proposed vote links to a brief before/after illustration and says precisely what is fixed versus open.
3. Publish focused GitHub Discussions (prefer Polls for V1 and appropriately scoped proposals for the rest), with stable numbering, a review window, and an explicit **informal / nonbinding** label. Do not imply Board ratification from reactions.
4. Only after the new canonical links are verified, reconcile and close/delete superseded 58 unvoted proposals. Preserve original [proposals](../proposals/) and [published index](../discussion-index.json) in Git and add replacement/supersession links. Keep technical work in Issues.
