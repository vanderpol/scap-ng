## Order of operations

1. Lock grammar and its validators; disallow silent defaults and ambiguous duplicate capability declarations.
2. Validate the full six-STIG source closure under the *actual* grammar and identify all remaining legacy tokens. Rebuild if needed.
3. Complete native compiler and semantic boundary cases, not just parsed-source reconstruction.
4. Migrate the editor to exactly that pinned source/schema; verify imports, structured edits and downloads.
5. Review coverage and publish a single concise 0.4.0 release packet, including failed/unresolved gates.

**Do not mark 0.4.0 final** merely because a workflow is green, a preview ZIP exists, or metadata is copied. An archive of OVAL annotations is not a reviewed NG-native scanner implementation guide.

## Migration blocker inventory — six-STIG audit (2026-10-20)

[Full successful audit run](https://github.com/vanderpol/scap-ng/actions/runs/39451201608) checked **4,001 source documents** in both YAML and JSON. The results agree across formats:

| Test-level declaration | Occurrences | Next action |
| --- | ---: | --- |
| Native `require.items / all_items_must` | 816 | Keep and validate against canonical schema |
| Older string `require` | 559 | Separate true existence-only cases from State-bearing uncommon match operators |
| Remaining top-level `states` | 172 | Map State-level aggregators and cardinality without changing six-state behavior |
| `states_match` | 128 | Require source-equivalent `and`/`or` or documented `one`/`odd` handling |
| `state_fields_require` at Test level | 108 | Preserve field-level cardinality before restructuring |

The 559 string cases include **156 at_least_one_exists**, **127 all_exist**, and **103 none_exist**, which are presence-only *candidates* to examine first, plus less-common matching combinations. These counts are **not** 559 distinct Assessments: categories overlap at the Test level and may appear multiple times across benchmarks.

**Acceptance consequence:** Gate 1 and Gate 3 remain PARTIAL. These documents were source-reversibly generated but are not all confirmed to satisfy one normalized 0.4.0 language. Do not remove those legacy requirements or rename them merely for a green run. Counts are now pinned as an audit regression baseline in `tools/audit_v04_authoring_blockers.py`; deliberate migrations must update the baseline and add equivalence evidence.
