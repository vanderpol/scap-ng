### Necessary semantics versus representation overhead

Independent root and relative config arrays can form a Cartesian product when two installations exist. Joining by installation changes the acquired scope and needs proof rather than automatic replacement. All-occurrence policy differs from effective last-directive/default policy; grepping nested includes is not an Apache interpreter. Paths from target data enter unquoted command strings.

Object status/completeness, Item and entity existence, item/state/variable quantifiers, Boolean nesting and acquisition scope are necessary semantics. Source comment/title, separate serialization wrappers and repeated command/regex construction are not independent security requirements. Named shared Objects and Variables SHALL remain referenceable.

## Methods investigated

A: shared typed acquisition of explicit directive occurrences, preserving the two source acquisition groups and four Tests. Reader still sees which group is required or optional. B: apache.configuration records keyed by installation/context, distinguishing explicit occurrences from effective values. B needs an Apache-version interpreter; effective values alone cannot implement explicit-presence requirements.

[Complete after sketch](../proposals/apache-keepalive.proposal.yaml) — all invented fields use the [experimental contract](../FEATURES.md). This sketch shows the proposed method, not a deployable lossless conversion; applicability/bindings remain unchanged unless separately reviewed. A no-change baseline remains valid.

## Cases and falsification

Two installations with different roots; absent explicit directives with favorable defaults; Off then On; MaxKeepAliveRequests 99/100/101/0; a VirtualHost override; nested/optional missing include; unreadable include; spaces in paths; no matching processes; nonzero command with partial stdout. The executable model isolates directive predicates, not these acquisition behaviors.

Executed cases are in [test_semantics.py](../experiments/test_semantics.py) and [results](../evidence/test-results.txt). Additional acquisition/OS cases above are specified, not executed. Per-record missing/error/unknown/multiple-match/partial-collection fixtures are synthetic language experiments, not evidence that source collectors behave that way.
