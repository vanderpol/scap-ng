Two Variables project home_dir. Five States include eight forbidden permission booleans. The non-system Test permits empty collections; the root Test requires at least one. File recursion follows symlinks, depth 1; effective filesystem defaults are evidence, not permission to substitute local exclusions.

### Necessary semantics versus representation overhead

A numeric mode<=0740 is incorrect: 0604 is numerically lower but grants other-read. Generic collapse of both Tests changes root missing-file behavior. The legacy complement has one operand; preserve checked-in importer handling and raise its portability ambiguity, rather than invent a second operand. Native clean-break permission booleans already solve most comparison readability.

Object status/completeness, Item and entity existence, item/state/variable quantifiers, Boolean nesting and acquisition scope are necessary semantics. Source comment/title, separate serialization wrappers and repeated command/regex construction are not independent security requirements. Named shared Objects and Variables SHALL remain referenceable.

## Methods investigated

A: existing Variables, named account Objects, native downward file selection and descriptive permission booleans; retain root/non-system quantifiers. B: an authoring library for account-home file selection expanded to the same graph, leaving all traversal choices explicit. No new permission test or mode field is justified.

[Complete after sketch](../proposals/home-file-permissions.proposal.yaml) — all invented fields use the [experimental contract](../FEATURES.md). This sketch shows the proposed method, not a deployable lossless conversion; applicability/bindings remain unchanged unless separately reviewed. A no-change baseline remains valid.

## Cases and falsification

UID999/1000; UID0 and home /; zero normal-user files versus zero root files; mode0604,0740,0700,04740; symlink loop, local/remote mount transition, unreadable home; directory dot entry excluded; duplicate home paths. Synthetic bit tests prove comparison only, not traversal equivalence.

Executed cases are in [test_semantics.py](../experiments/test_semantics.py) and [results](../evidence/test-results.txt). Additional acquisition/OS cases above are specified, not executed. Per-record missing/error/unknown/multiple-match/partial-collection fixtures are synthetic language experiments, not evidence that source collectors behave that way.

## Cost, confidence and unresolved decisions

Existing capability composition: low language cost, meaningful naming benefit. Traversal implementation remains high and belongs to scanner. Shell find is rejected. Source filesystem semantics cannot silently be changed to local-only while calling conversion faithful.

Established: inherited source graph and references. Inferred: intended scope explained from Check Text, separately from source behavior. Unresolved: collector execution, target reachability of synthetic boundaries and independent assessor agreement. See [comparison](../COMPARISON.md) and [questions](../DECISIONS.md).
