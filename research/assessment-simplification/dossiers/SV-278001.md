## Complete baseline dependency explanation

Five Tests, four Objects, three constant regex-list Variables and five States. PowerShell formats ACE fields to strings and filters numeric RegistryRights displays before regex comparison. WMI DomainRole records distinguish 4/5 from other roles. Every returned ACE string must match some allowed pattern; this is not a required-principal equality check.

Closure counts: `{"definitions": 1, "objects": 4, "states": 5, "tests": 5, "variables": 3}`; [original OVAL](../evidence/ms_windows_server_2025/SV-278001/source-oval.xml), [typed dependency edges and source attributes](../evidence/ms_windows_server_2025/SV-278001/graph.json), [unchanged before Assessment](../samples/ms_windows_server_2025/assessments/automated/niwc.ms_windows_server_2025.SV-278001.automated.assessment.yaml).

### Necessary semantics versus representation overhead

Filtering numeric-right displays can omit an ACE from assessment; English IdentityReference/enum formatting is fragile. All observed ACEs allowed does not prove every default ACE exists. Requiring a complete default table is a policy change, while switching to effective rights would change the object of review.

Object status/completeness, Item and entity existence, item/state/variable quantifiers, Boolean nesting and acquisition scope are necessary semantics. Source comment/title, separate serialization wrappers and repeated command/regex construction are not independent security requirements. Named shared Objects and Variables SHALL remain referenceable.

## Methods investigated

A: typed explicit registry ACE records preserving access type/inheritance/propagation and source whitelist semantics. B: required default ACL policy comparison, separately identified as intent/coverage refinement. Retain WMI-authored platform/role facts; do not add scanner OS magic.

[Complete after sketch](../proposals/registry-ace-records.proposal.yaml) — all invented fields use the [experimental contract](../FEATURES.md). This sketch shows the proposed method, not a deployable lossless conversion; applicability/bindings remain unchanged unless separately reviewed. A no-change baseline remains valid.

## Cases and falsification

Allowed subset missing SYSTEM; numeric-right ACE hidden; localized principal names; DC DomainRole 4/5; role unknown; custom application SID; deny/allow ordering; null versus empty DACL; inaccessible registry. Structural ACE checks and effective access have separate contracts.

Executed cases are in [test_semantics.py](../experiments/test_semantics.py) and [results](../evidence/test-results.txt). Additional acquisition/OS cases above are specified, not executed. Per-record missing/error/unknown/multiple-match/partial-collection fixtures are synthetic language experiments, not evidence that source collectors behave that way.

## Cost, confidence and unresolved decisions

Medium structured acquisition cost; needs generic-mask mapping and SID resolution. A typed ACE schema is clearer than regex strings but cannot claim identical behavior until representation omissions are accounted for.
