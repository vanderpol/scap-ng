### Necessary semantics versus representation overhead

The Tests titled b64 root lsetxattr and removexattr use b32 patterns, duplicating their b32 branches. A table must retain these anomalies for faithful comparison, not silently generate a corrected 2×2×6 matrix. Source uses regex spelling/ordering restrictions; a semantic audit parser deliberately accepts some strings the regex rejects.

Object status/completeness, Item and entity existence, item/state/variable quantifiers, Boolean nesting and acquisition scope are necessary semantics. Source comment/title, separate serialization wrappers and repeated command/regex construction are not independent security requirements. Named shared Objects and Variables SHALL remain referenceable.

## Cases and falsification

Loaded missing while persisted complete; b64 root absent for lsetxattr/removexattr; reordered -F fields; split versus combined syscall lists; commented rule; unset/-1/4294967295; unknown extra success filter; unreadable file; duplicate matches; incomplete query. Parser SHALL return unsupported/unknown for conditions whose meaning it cannot establish, not ignore them.

Executed cases are in [test_semantics.py](../experiments/test_semantics.py) and [results](../evidence/test-results.txt). Additional acquisition/OS cases above are specified, not executed. Per-record missing/error/unknown/multiple-match/partial-collection fixtures are synthetic language experiments, not evidence that source collectors behave that way.

Parsed audit acquisition is high cost: architecture-specific syscall mapping, rule ordering, exclude/never rules, persisted includes and kernel state are unimplemented. No arbitrary command input.
