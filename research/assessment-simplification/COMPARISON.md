# What became simpler, and at what cost?

Counts describe top-level authored nodes, excluding row entries, predicate fields, condition logic and collector implementation. They SHALL NOT be reported as equivalent reductions in security complexity or runtime work. Exact per-case counts are in [authoring-counts.json](evidence/authoring-counts.json). Before snapshots remain immutable.

| Opportunity | Classification | Human benefit | Scanner cost | Compatibility risk | Current evidence |
| --- | --- | --- | --- | --- | --- |

| Crypto finite back-end table | Authoring tooling | Twelve paths/expectations remain visible without three repeated node wrappers | None if expanded faithfully | Low/moderate: canonical path versus raw target; existence per row | Row contract and bounded source/table comparisons; target symlink behavior unproven |

The strongest discovery is where **not** to change the language: finite repetition can be handled before runtime; cookie flag conjunction and typed-record field evaluation already fit existing semantics; permission booleans are preferable to an encoded numeric shortcut. New collector work is promising but moves substantial complexity into scanner implementation, so shorter YAML is not sufficient evidence to adopt it.

No performance measurements, target scanner agreement, enterprise memory estimates or field-author usability study have been run. Batched acquisition SHOULD amortize queries, but that is an implementation hypothesis. Preserving named shared Objects may permit caching; cache identity/snapshot consistency and privilege must be tested. These samples are a purposive set, not a corpus-wide prevalence claim.
