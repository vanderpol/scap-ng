# Collected Item readability audit for 0.2.0

Status: **initial complete field inventory and candidate review**, not approved schema extensions or a target-collection implementation. Owner request, 2026-10-03: review all collected Item schemas for additional attributes that make results more intuitive, such as Unix file user/group names. Provenance: **Evidence/Audit**; field-addition suggestions below are proposals.

## Coverage and reproduction

Reviewed the collected fields generated by all **100** current capability mappings against generator `tools/generate_capability_schema.py`. **99** generate a collected Item definition; `independent.unknown` intentionally has no observation contract. The generic `collected-item.schema.json` already permits typed fields, per-value redaction/status, an imported marker and provenance. Capability fragments close their field vocabularies; adding names to a generic result alone will not make them valid for `unix.file`.

The [complete compressed JSON inventory](collected-item-fields-2026-10-03.json.gz) records every generated field contract, mapping hashes and generated-schema hashes. Source capability mappings and the generator match baseline `cc1ce5168e03179be42e2f79c7b4a21b7ccefe94`; the accompanying 0.1.0 enforcement fixes do not change capability field generation. Gzip avoids committing thousands of repeated schema-fragment lines; decompress it with a standard gzip reader.

Reproduction: `python tools/inventory_collected_item_fields.py --output research/iterations/003/evidence/collected-item-fields-2026-10-03.json.gz` (omit `.gz` for readable uncompressed JSON).

All 100 mappings generated without error. This checks generation and inventories field structure. It does not prove target field acquisition, correctness, mandatory evidence, or runtime equivalence. The inventory includes reusable JSON Schema fragments rather than actual observed values.

## Proposed contract rules

1. Observed identity SHALL remain distinguishable from a resolved display name. Numeric UID/GID/SID values SHALL NOT be replaced by explanatory labels.
2. Name resolution SHALL use the assessed target's identity context; scanner-host account lookup SHALL NOT be substituted for target evidence. Results SHOULD retain resolution status, source and timing where needed to interpret ambiguity or changes.
3. Optional explanatory enrichment failure SHOULD NOT change the result of a Test that uses only observed numeric identity. Tests that intentionally compare resolved names require separately specified acquisition/error semantics.
4. Derived presentations, such as Unix mode strings and date/unit renderings, SHALL identify their derivation and retain the authoritative typed values. They SHALL NOT become an independent source of truth.
5. Result-only explanatory attributes SHALL NOT automatically become Object selectors or State predicates. The reviewed mapping/generator contract needs an explicit result-field extension mechanism where such attributes are adopted.
6. Enrichment SHALL respect redaction, evidence limits and target context. An imported Item SHALL preserve the original observation/resolution provenance; importing SHALL NOT silently re-resolve a name against a different system or time.

## Unix file acceptance cases before promotion

Cover resolved UID/GID, unmapped IDs, lookup denial/error/unavailable service, aliases, account/group rename between collection and lookup, duplicate names in distinct identity namespaces, containers/chroots, remote identity service, and redacted names. Verify a numeric ownership comparison has identical technical truth with enrichment enabled, unavailable or omitted. If name predicates are adopted, test their unknown/error behavior independently. For permission presentations, verify all 4096 modes and distinguish ACL presence from base permission bits. No such enrichment evaluator or target tests have been run in this audit.

## What remains

Implement changes in the versioned result/capability contracts after those choices are agreed. Conditional evaluation and Item inclusion remain separate 0.2.0 work; editor R&D follows those semantics rather than determining them.
