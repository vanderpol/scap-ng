# Iteration 001 Full-Benchmark Prototypes

These are the primary iteration 001 architecture prototypes. The authoring source is intentionally **file-oriented**; aggregate policy/automation YAML documents are not the source model.

## Benchmark families

Iteration 001 contains three seven-rule STIG-like benchmark families:

- Windows Client
- Windows Server
- Linux

Each is represented in both candidate architectures and published in both policy-only and automated form, producing **12 signed prototype `.scapng` bundles**.

## Where to start

Read `source-layout.md` first. For Windows cross-STIG reuse, then read `windows-assessment-reuse-crosswalk.md` and `windows-assessment-reuse-map.yaml`.

The two Windows policies intentionally use different policy rule IDs, titles, and references while sharing five equivalent technical assessment concepts.

## Candidate A — combined rule

```text
combined-rule/<benchmark>/
  source/
    policy/
      benchmark.yaml
      profile.yaml
      provenance.yaml
      rules/<rule-id>.yaml
    automated/
      rules/<rule-id>.yaml
  results/
  dist/
```

The policy tree represents policy-only publication. The automated rule files repeat the policy fields and place automation inline.

## Candidate B — split policy / assessment / binding

```text
split-policy-assessment-binding/<benchmark>/
  source/
    policy/
      benchmark.yaml
      profile.yaml
      provenance.yaml
      rules/<rule-id>.yaml
    automation/
      benchmark.yaml
      bindings.yaml
      assessments/<benchmark-specific-assessment>.yaml
  results/
  dist/

split-policy-assessment-binding/shared-assessments/windows/
  <shared-assessment>.yaml
```

The same five Windows assessment files are bound to rule IDs in both Windows Client and Windows Server. The build resolves them into each signed, self-contained scanner package.

## Reproducibility

Packages are generated by `research/iterations/001/tools/build_full_benchmarks.py` and verified by `tools/verify_scapng_prototype_bundle.py`. The GitHub Actions workflow rebuilds and verifies all 12 bundles.

Each benchmark has complete policy-only and automated/mixed-method result examples.

All content is illustrative and must not be interpreted as an official DISA baseline.
